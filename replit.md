# LaunchFlow AI — Workspace

## Overview

LaunchFlow AI is a production-grade B2B SaaS autonomous GTM strategy orchestrator. It uses AI agents (simulated) to research competitors, generate marketing assets, and produce a complete go-to-market strategy with human-in-the-loop approval.

pnpm workspace monorepo using TypeScript. Each package manages its own dependencies.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **Frontend**: React + Vite (artifacts/launchflow, previewPath `/`)
- **Backend**: Express 5 (artifacts/api-server, previewPath `/api`)
- **Auth**: Replit Auth (OIDC/PKCE via openid-client) — lib/replit-auth-web
- **Database**: PostgreSQL + Drizzle ORM (lib/db)
- **Validation**: Zod, generated by Orval from OpenAPI spec
- **API codegen**: Orval — spec in lib/api-spec/openapi.yaml
- **Build**: esbuild (api-server), Vite (frontend)

## Artifact Ports

- `artifacts/launchflow`: port 20143, previewPath `/`
- `artifacts/api-server`: port 8080, previewPath `/api`

## DB Schema (lib/db/src/schema/)

- `auth.ts` — sessions, usersTable (Replit Auth: id=OIDC sub claim)
- `launchflow.ts` — gtmProjects, competitorData, marketingAssets (with pgEnums)

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)

## API Routes (all under /api)

- `GET /api/healthz` — health check
- `GET /api/auth/user` — current user
- `GET /api/login` — begin OIDC login
- `GET /api/callback` — OIDC callback
- `GET /api/logout` — logout + end session
- `GET/POST /api/projects` — list/create GTM projects
- `GET/PATCH/DELETE /api/projects/:id` — project CRUD
- `POST /api/projects/:id/run-agents` — trigger AI agent simulation
- `POST /api/projects/:id/approve` — human approval
- `GET /api/projects/:id/assets` — list marketing assets
- `PATCH /api/projects/:id/assets/:assetId` — approve/update asset
- `GET /api/projects/:id/competitors` — list competitor data
- `GET /api/dashboard/stats` — aggregated stats

## Frontend Pages

- `/` — Dashboard (stats, recent projects)
- `/projects` — Project list
- `/projects/new` — Create new GTM project
- `/projects/:id` — Project detail (Overview, Assets, Competitors tabs)

## Orval Config Notes

- The `zod` orval config uses `mode: "single"` and `target: "generated/api.ts"` to avoid barrel file conflicts
- `lib/api-zod/src/index.ts` exports only from `./generated/api` (no types barrel to avoid duplicates)
- `lib/replit-auth-web/tsconfig.json` uses `"types": []` (no vite/client types — use-auth.ts uses dynamic import.meta access with @ts-ignore)

## Agent Simulation

When `POST /api/projects/:id/run-agents` is called:
1. Project status → "processing", all agent statuses → "running"
2. After 3s delay: inserts 2 competitor records + 3 marketing assets (positioning doc, cold email, ad copy)
3. Project status → "awaiting_approval", agent statuses → "completed"
4. User approves via `POST /api/projects/:id/approve`
